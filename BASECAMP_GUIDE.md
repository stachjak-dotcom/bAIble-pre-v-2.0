# Basecamp Guide

Basecamp is the contextual and relational workspace for a project.

It becomes useful when ordinary conversation or flat files make it difficult to preserve relationships between observations, hypotheses, decisions, experiments, projects, evidence, and lessons.

It is not a source of truth by itself.

## What Basecamp is for

A project does not only produce files and completed tasks. It also accumulates:

- why a decision was made;
- what was observed before the decision;
- which experiment produced a result;
- which evidence supports a conclusion;
- which lessons changed the way the project works;
- how ideas and discoveries connect over time.

Basecamp gives these relationships a place to live.

That makes it useful not only for **remembering the project**, but for **understanding how the project grows**.

## Simple model

**SESSION → OBSERVATION → HYPOTHESIS → PATTERN → DECISION → EXPERIMENT → RESULT → EVIDENCE → LESSON**

These are different kinds of things. An observation is not automatically a hypothesis. A repeated pattern is not automatically proven. A decision is not evidence that the decision was correct. A map of relationships is not reality itself.

## Context is not truth

Basecamp can preserve where an observation came from, which ideas were connected, what changed, which decisions depended on which evidence, and which lessons came from which experiments.

It should never silently upgrade an inferred relationship into a fact.

## Candidate patterns

Use:

**OBSERVED → CANDIDATE → TESTED → CONFIRMED / REJECTED / UNCERTAIN**

Frequency can be a signal. Frequency alone is not proof.

## Human and AI views

A project may maintain different views for human navigation, AI retrieval, audit/evidence, or visualization. Different views can represent the same underlying records differently.

A convenient visualization is not automatically authoritative semantics.

## Start without a graph database

Begin with structured records such as decisions, observations, experiments, lessons, provenance records, and handoffs.

Add a database, graph, map, or 3D interface only when the relationship problem justifies it.

## Missing context

When essential context is missing:

1. identify what is missing;
2. locate a source;
3. ask the human when necessary;
4. record uncertainty;
5. do not fill the gap with a plausible invention.

## Visual maps

A spatial or 3D map can be a useful projection of relationships. Keep the underlying records independently inspectable.
