# Bootstrap a new workspace

A new user should be able to start without hidden context.

1. Read `README.md`, `BIBLE.md`, and `TERMINOLOGY.md`.
2. Create your own workspace/repository. Names are your choice.
3. Decide visibility deliberately.
4. Create durable project memory, for example `PROJECT_CONTEXT.md`, `PROJECT_STATE.md`, `DECISIONS.md`, `EXPERIMENTS.md`, and `LESSONS_LEARNED.md`.
5. Define each agent's role, tools, scope, approval level, authoritative sources, verification method, and handoff format.
6. Run a first Reality Check: what can the agent access, what can it not access, which source is authoritative, what is assumed, and what needs verification?
7. Run one small, reversible experiment.
8. Add orchestration only when coordination becomes useful.
9. Add contextual/relational knowledge only when it solves a real problem.
10. Add integration infrastructure when multiple tools, repositories, CI systems, or workflows need coordination.
11. Add a watchdog last. It should detect and report before it autonomously repairs.
12. Promote lessons into permanent rules only after validation.

## First milestone

A new human can understand the framework, create a workspace, give a bounded task, observe a Reality Check, verify the result, and preserve a lesson without hidden context.
