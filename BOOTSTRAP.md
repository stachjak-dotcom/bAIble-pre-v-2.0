# Bootstrap a New Workspace

A new user should be able to start without hidden context.

1. Read [START_HERE.md](START_HERE.md), [BIBLE.md](BIBLE.md), and [TERMINOLOGY.md](TERMINOLOGY.md).
2. Follow [REPOSITORY_BOOTSTRAP.md](REPOSITORY_BOOTSTRAP.md) to establish an appropriate private workspace.
3. Decide visibility deliberately.
4. Copy only the templates you actually need from [WORKSPACE_TEMPLATE](WORKSPACE_TEMPLATE/).
5. Create an [AGENT_PROFILE](AGENT_PROFILE.md) for each agent that will perform meaningful work.
6. Define role, tools, systems/repositories, scope, authority, approval level, authoritative sources, verification responsibility, and handoff format.
7. Run a first Reality Check: what can the agent access, what can it not access, which source is authoritative, what is assumed, and what needs verification?
8. Record material project rules explicitly using [WORKSPACE_TEMPLATE/DECISIONS.md](WORKSPACE_TEMPLATE/DECISIONS.md).
9. Run one small, reversible experiment using [EXPERIMENTS.md](EXPERIMENTS.md).
10. Record verification separately using [VERIFICATION.md](VERIFICATION.md).
11. Transfer work using [HANDOFF.md](HANDOFF.md) when another human, agent, tool, or session takes over.
12. Add rAIda only when coordination becomes useful.
13. Add UnAiversed only when relational context solves a real problem.
14. Add an integration layer only when multiple execution surfaces need coordination.
15. Add a watchdog only after the workflow is observable.
16. Promote lessons into permanent rules only after validation.

## Authority rule

bAIble requires authority and approval to be explicit, but does not invent project-specific authority. If authority is unknown for a material action, record UNKNOWN and stop or escalate as appropriate.

## First milestone

A new human can understand the framework, establish an appropriate private workspace, give a bounded task, define agent boundaries, observe a Reality Check, verify the result, hand off the work, and preserve a lesson without hidden context.

## Bootstrap failure is useful

If a fresh start forces invention of a core rule about authority, evidence, verification, scope, security, or Reality Check, record it as a documentation gap instead of silently inventing the rule.
